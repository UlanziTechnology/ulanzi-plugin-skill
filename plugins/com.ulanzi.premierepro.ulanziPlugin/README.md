## 2026-10-27 Mac 源码补丁：独立的移动容忍与鼠标恢复策略

Mac 原生定位期间的小幅移动容忍改为每轴最多5个坐标点；鼠标原本在安全时间线内时，越出区域仍取消。发送后恢复鼠标使用独立判断，继续要求当前位置与缩放锚点每轴距离严格小于2点、仍在安全区域内且没有按下鼠标；恢复目标为发送滚轮前的最新位置，避免把已容忍的小幅移动拉回。

## Windows 播放头锚点光标停留补丁（2026-10-19）

按用户要求：唯一播放头可见时，旋转把鼠标移到播放头对应的安全缩放位置，停转后也不恢复原位置。鼠标已经在锚点时不重复移动，也不重复等待移入悬停；实际移入仍等待 20ms，发送后保留 25ms。发送期间用户移动鼠标会拒绝/让出控制，不强行拉回。未识别播放头时，鼠标/中心兜底及其恢复行为保持不变，不点击时间尺或改变播放时间。

成功日志标记 `nativeRevision: playhead-cursor-stay-v1`；播放头模式为 `cursorMode: stay`，`restored: false` 是预期行为，使用 `cursorAtAnchor` 判断光标是否留在锚点。此补丁只更新 Windows 原生辅助程序，Mac 源码和二进制未因本补丁改变。下文的“恢复原位”记录为此前行为。

## 0.1.5：Windows 连续旋转与 Mac 结构定位源码

10:29 实体旋钮复测确认仍有卡顿，原生日志具体原因为 `mouse-capture`：PR 内部持有鼠标捕获被旧判断误当成用户拖动。现仅允许捕获属于已验证 PR 进程且根窗口为当前主窗口的情况；其他/无法验证的捕获仍拒绝。物理鼠标按钮、修饰键、菜单/窗口移动、发送期间光标移动及前台检查继续保留，不调用 ReleaseCapture。成功响应标记 `nativeRevision: capture-owner-v1`，用于区别热更新前后的辅助程序；实体手感需再验收。

Windows 移除“鼠标坐标变化后强制暂停 300ms”的跨请求冷却；1px 抖动可复用锚点，较大移动重新取锚点，不积累额外暂停。仅在光标恢复成功后记录连续手势位置，恢复失败或用户移走光标时使锚点失效。发送期间的移动、拖动、修饰键、菜单和前台保护继续保留。每次仍实时检查前台 HWND/PID，缓存进程身份查询以减少开销。新增有界 `timeline-zoom-native.log` 记录具体拒绝原因。

用户此前一轮日志为 23 次成功、84 次 ZOOM_USER_INPUT_ACTIVE、2 次取消，成功耗时平均 124ms。该日志没有细分鼠标拒绝原因，不能认定每次都是用户移动；逐像素跨请求比较和 300ms 冷却是代码中明确的停顿放大因素。本轮独立有界测试六步全部成功，约 61–92ms，三组正反向的时间尺恢复原结果、播放时间不变。该数据不是实体旋钮端到端延迟，仍需用户确认手感。

| --- | --- | --- |

关键帧是调色的附属行为，不是第七个 Action。4.3 轨迹球、调音（4.4 D2）、独立剪切/播放等快捷键 Action **未纳入本版**。未扩展为全局悬浮窗。

饱和度采用 Premiere 实际 **0–200，100 为中性值**；不是原文误写的 -100–100。

功能按钮及旋钮固定参数的下拉选项均按截图的九项顺序排列。色彩（Tint）、白色、黑色与色温一样按 -100～100 增量调节，默认每格 1；曝光每格 0.1。旋钮默认循环使用上述顺序；旧六项默认循环自动更新，已自定义的循环子集/顺序保留。原有按钮选定参数和功能组不变。

3. 参考 AE 插件，初始化自动开启未签名 CEP 扩展加载：检查当前用户 CSXS 10/11/12 的 `PlayerDebugMode`，未启用时设置为字符串 `1` 并回读确认，已启用则跳过写入。Windows 写 HKCU 注册表，macOS 写用户偏好设置；无需用户手动执行命令。**此设置影响当前用户对应版本的所有 CEP 扩展，不只本插件**。查询临时失败立即重试一次；初始化仍失败时后台每 10 秒复查，全部成功后自动清除错误提示。持续失败时检查系统权限和日志。此流程不生成 Adobe 签名。
4. 保存工程，重启 Premiere 和 Ulanzi Studio 以加载新版。桥接随 PR 激活在后台自动启动，不需要手动打开或保持任何窗口。两款软件启动顺序不限；另一端尚未启动时会等待，普通空闲断线按 0.5–10 秒退避重连。
5. 先用独立测试工程和测试素材，不要直接在重要剪辑上验证。先放一个逐帧 Action 测试通信，再放调色旋钮/功能按钮，并设相同 `groupId`。

需要排查时，打开“窗口 → 扩展（或扩展〔旧版〕）→ **Ulanzi Premiere Bridge Diagnostics**”，可查看状态、刷新或主动重连。诊断面板与后台连接独立，关闭它不会断开桥接。若未响应，请先确认安装及未签名扩展设置，再保存工程并重启 PR。

配置页顶部会区分应用未启动与桥接未连接。未连接时每秒检查一次 PR 进程；首次检测到应用运行后先等待 15 秒，以便扩展完成启动。等待阶段补充首次使用或更新插件后需保存项目、完全退出并重新打开 PR 的说明；持续未连接时直接提示上述操作，重新打开后自动连接，不再只提示“检查扩展”。已认证连接时显示“Premiere Pro 桥接已连接”，不再轮询进程。端口占用、配对失败和需要人工恢复的安全暂停会分别提示。无法读取进程状态时会明确表示暂时无法确认，不判断为“应用未启动”。进程存在只能证明 PR 已运行，无法仅凭未连接进一步判定扩展未安装或加载失败。更新主服务后需重启 Ulanzi Studio。

功能切换仍会更新设备按键/旋钮名称；若诊断面板已打开，也会短暂提示当前参数。**不是覆盖 PR 工作区的原生 Toast**，后台不会自动弹窗或抢焦点。

## 安全与恢复

- 仅监听本机 `127.0.0.1:49631`，随机令牌配对，拒绝普通网页 Origin。配对文件在用户目录 `.ulanzi-premiere/bridge.json`；不要上传/分享该文件。
- 一次一个 ExtendScript 调用，连续同向旋转合并，排队有上限/过期保护；超时或连接中断不重放写入。
- 时间线缩放使用独立滚轮队列，不受 CEP 排队影响。Windows 常驻辅助程序每次检查真实前台，不启动旧的前台查询或快捷键辅助流程；超过 250 毫秒的积压丢弃。日志写入 `%APPDATA%\Ulanzi\UlanziDeck\logs\com.ulanzi.ulanzistudio.premierepro\timeline-zoom.log`，记录方向、锚点、定位和辅助程序耗时，不代表 PR 绘制或端到端延迟。约 2 MiB 时轮换，保留当前和上一份。
- 遇到 `PARTIAL_MUTATION`、超时或结果不明，**停止操作，先查看 PR 时间线和 AME 队列**，必要时用 PR 撤销或恢复工程备份，然后在 **Ulanzi Premiere Bridge Diagnostics** 手动“重新连接”。此类安全停止不会自动恢复，也不会重放操作；宿主请求尚未结束时不允许重连。程序不承诺 CEP 具有数据库式原子事务。
- 原生接口能验证的不安全场景会拒绝执行。CEP 未提供可靠检测的字幕/同步锁定情况不能被这种保护完全覆盖；本版不要对含字幕或复杂同步锁定的序列使用波纹修剪。
- Lumetri 参数通过组件 matchName 与已知语言的“基本校正”布局校验识别，不猜未知参数序号。若报布局不支持，请保留诊断信息并用 PR 手动调整。
- 执行导出前重新核对活动序列 ID、预设、扩展名和输出是否存在；动作被删除/配置被修改后，尚未发送的导出会取消。已经交给 PR/AME 的调用无法撤回。
- 快速导出先验证 `.epr` 预设；只有 ME 队列模式检查 AME 安装。Windows 检查运行程序路径、App Paths、卸载登记及常用 Adobe 安装目录，并确认可执行文件存在；macOS 检查系统及用户 Applications 下的 AME 应用。ME 未找到或检查失败时不提交队列，PR 直接导出不受该检查影响。无需提前启动 AME；检查不保证 PR/AME 版本兼容或后续编码成功。未登记且位于自定义目录的 AME，可先手动启动后在 Windows 重试。

## 开发与交付结构

- `plugin/app.js`：Ulanzi Node 主入口。
- `plugin/PluginController.js`：六个 Action、实例设置、分组与反馈。
- `plugin/services/`：连续事件队列、预设与安全路径、前台检测。
- `plugin/bridge/`：本地 WebSocket 桥接。
- `plugin/cep/com.ulanzi.premierepro.bridge/`：CEP 隐形后台、独立诊断面板、CSInterface、ExtendScript 宿主实现。
- `property-inspector/`：六个 Action 共用配置页；八语言在插件根目录。
- `libs/`：本次 GitHub 刷新后的官方 Ulanzi SDK 原样副本。

源工作区 `tests/` 包含宿主 mock、Node/CEP 协议、配置/队列/导出安全测试；在工作区执行 `node --test tests/*.mjs`。`tools/preview-server.mjs` 只是配置页预览，不会连接真实 PR。完整验证状态见交付的 `VALIDATION.md`。

## 0.1.3：固定 Mac 滚轮缩放（2026-10-18）

缩放固定使用原生常驻辅助程序，每格一个滚轮小步，自动选择锚点。顺时针放大、逆时针缩小。旧按钮保存过的模式、步长、锚点及自定义快捷键全部忽略；配置页只保留功能提示。已移除快捷键执行路径及其前台查询进程。Windows 和 macOS 12 暂不支持此 Action，会明确提示。

辅助功能权限用于读取时间线布局和发送滚轮。macOS 15.2+ 已有屏幕录制权限时，在一次连续旋转开始时尝试识别时间线内清晰且唯一的蓝色播放头线；图像只在内存中处理，不保存或上传。没有该权限、较旧系统、检测不明确时使用时间线内鼠标位置，否则视窗中心，不自动请求屏幕录制权限。连续旋转期间保持同一锚点选择，不移动播放头时间。此版本只验证中文/英文 Premiere 面板；未识别的布局会提示显示序列时间线。

发送间隔至少 16ms，最多等待 6 个小步，反向或切换按钮丢弃旧方向的待发送输入。每次发送检查 PR 前台、窗口及鼠标操作，恢复事件改变的鼠标坐标；检测到用户移动鼠标时不强行复位。到最大/最小倍率由 PR 自行限制。发送失败不会自动补发快捷键，避免重复缩放。

辅助程序包含 arm64 / x86_64 两种架构，可用 `sh plugin/native/build-macos.sh` 重建；本机实测仅覆盖 Apple Silicon。首步需要布局/画面识别，可能比后续步慢。本次 Node→辅助程序→PR 联调首步约 127ms，后续约 13–37ms（不含屏幕绘制和实体旋钮输入时间）。真实设备手感、多显示器和更复杂工作区仍需验收。

更新后重启 Ulanzi Studio 加载新主服务，无需因本次更新重启 Premiere。缩放诊断日志：`~/Library/Application Support/Ulanzi/UlanziDeck/logs/com.ulanzi.ulanzistudio.premierepro/timeline-zoom.log`。

2026-10-18 用户重启 Ulanzi 后反馈手感顺滑。该次日志共 481 次滚轮成功发送，其中播放头锚点 402 次、鼠标锚点 79 次；5 次 ACTION_CANCELLED，无快捷键发送记录。发送日志确认输入路径与锚点选择，不等于逐帧验证 Premiere 的绘制结果。
